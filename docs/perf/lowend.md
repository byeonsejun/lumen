# 저사양 노트북 fps — 시뮬레이션 측정 (2026-11-05)

## 무엇을 쟀고, 무엇을 못 쟀나
저사양 노트북 실기기가 없어서 **M1 맥북에어(8GB)에서 조건을 바꿔 흉내 냈다.** 실제 인텔 내장 GPU 노트북의 숫자는 아니다.

| 시나리오 | 방법 | 흉내 내는 것 |
|---|---|---|
| M1 그대로 | 1440×900 @2x, Chrome(WebGPU) | 기준 |
| CPU 4배 · 6배 감속 | CDP `Emulation.setCPUThrottlingRate` | 느린 CPU (GPU 는 M1 그대로) |
| GPU 부하 ≈2.8배 | 2560×1440 @2x — 그릴 픽셀이 1440×900 @2x 의 약 2.8배 | 약한 GPU (픽셀 수에 비례하는 부담만) |
| CPU 4배 + GPU 부하 ≈2.8배 | 위 둘을 함께 | 저사양 노트북에 가장 가까운 조합 |
| GPU 없음 | 헤드리스 Chrome(SwiftShader, 소프트웨어 렌더링) | GPU 가속이 꺼진 기기 · 바닥선 |

- 측정: `?debug` 화면 표시(렌더러 · 품질 단계 · 1초 평균 fps)를 1초마다 읽었다. 처음 3초(셰이더 컴파일 · 모델 디코딩)는 뺐다
- 쇼룸은 22초 동안 끝까지 천천히 스크롤, 상품 상세 · 장바구니 방(가구 7개)은 15초 가만히
- 시나리오마다 두 번씩. 스크립트는 로컬 `.superpowers/fps.cjs`(`next start -p 3200`)
- 품질 단계: 0 = 그림자 · 빛 번짐 없음, 1 = 그림자 1024 · 빛 번짐, 2 = 그림자 2048 · AO · 2k 텍스처

## 결과 (고치기 전, 두 번 중 나쁜 쪽)
fps 는 중앙값 / 하위 10%. 품질 단계는 1초마다 찍은 값.

| 시나리오 | 쇼룸 | 상품 상세 | 장바구니 방 |
|---|---|---|---|
| M1 그대로 | 60 / 58 · 단계 2 유지 | 60 / 60 · 2 | 60 / 60 · 2 |
| CPU 4배 | 60 / 47 · 2 | 60 / 60 · 2 | 52 / 10 · 2→1→2 |
| CPU 6배 | 55 / 4 · 2→1→0→1→2 | 60 / 60 · 2 | 59 / 1 · 2→0→1 |
| GPU 부하 ≈2.8배 | 50 / 20 · **2↔1 을 9번 오르내림** | 60 / 60 · 2 | 48 / 48 · 2 |
| CPU 4배 + GPU ≈2.8배 | 51 / 17 · **2↔1 을 9번 오르내림** | 60 / 60 · 2 | 48 / 46 · 2 |
| GPU 없음 | 7 / 6 · 0 | 17 / 17 · 0 | 7 / 7 · 0 |

## 찾은 것: 약한 GPU 에서 품질이 4초마다 깜빡였다
GPU 부하를 올리면 쇼룸이 `2221112111211121112111` 처럼 오르내렸다. 2단계에서 30fps 아래로 떨어져 1단계로 내리면 1단계는 60fps 로 넉넉하니 두 창(2초) 뒤 다시 2단계로 오르고, 거기서 또 떨어진다. 화면에서는 그림자와 해상도가 4초마다 바뀌어 보인다.

규칙에 "한 번 실패한 단계는 한동안 다시 오르지 않는다"를 넣었다(`src/three/quality/policy.ts` 의 `recordDrop` · `capFor`, 단위 테스트로 고정).
- 내려온 단계는 15초 동안 막는다. 같은 단계가 또 실패하면 30초, 60초로 늘린다
- 막힌 단계를 건너뛰어 오르지 않는다(1단계가 막혀 있으면 0단계에서 2단계로 바로 가지 않는다)
- 기록은 페이지를 옮겨도 이어진다. 품질 단계가 원래 페이지를 넘어 유지되기 때문에, 기록만 사라지면 상세에 들어가자마자 막아 둔 단계를 다시 시도한다

| 쇼룸 22초 | 단계 변화 | 중앙값 | 하위 10% |
|---|---|---|---|
| GPU ≈2.8배 — 전 | 9 · 8번 | 50 · 57 | 20 · 20 |
| GPU ≈2.8배 — 후 | 3 · 3번 | 60 · 60 | 21 · 33 |
| CPU 4배 + GPU ≈2.8배 — 전 | 9 · 8번 | 51 · 58 | 17 · 32 |
| CPU 4배 + GPU ≈2.8배 — 후 | 4 · 4번 | 60 · 60 | 50 · 52 |

고친 뒤에는 한 번 내려간 단계에서 버티다가 15초 뒤 한 번만 다시 시도한다(`2211111111111111121111`).

## 읽는 법
- **상품 상세는 모든 GPU 조건에서 60fps** 였다. 가구 하나 · 그림자 하나라 가볍다
- **장바구니 방은 GPU 부하에서 2단계 48fps 로 안정** — 30 아래로 안 떨어져 내리지 않는다. 오르는 기준(58)에도 못 미쳐 그대로 머문다
- CPU 감속에서의 1~10fps 순간값은 페이지 진입 직후 모델 디코딩이 3초를 넘긴 구간이다. 계속 느린 게 아니라 로딩이 길어진 것이고, 이때 단계가 한두 번 내려갔다 돌아온다
- **GPU 가 아예 없으면 0단계에서도 쇼룸 7fps** 다. 3D 는 돌지만 매끄럽지 않다
  → 같은 날 사진으로 돌렸다(`src/three/capability.ts` 의 `isSoftwareRenderer`, `policy.ts` 의 `tooSlowFor3D`).
  렌더러 이름이 SwiftShader · llvmpipe · Basic Render Driver 등이면 처음부터 사진, 이름으로 못 잡으면 0단계 4초 연속 10fps 미만일 때 사진으로 바꾼다.
  `?renderer=` 로 정해 온 경우는 바꾸지 않는다(e2e · 디버그). 헤드 Chrome(M1)은 그대로 WebGPU 3D, 헤드리스(SwiftShader)는 사진인 것을 확인(`.superpowers/gpu-check.cjs`)

## 상품 상세 LCP 다시 보기 (2026-11-04)
5.1초는 실제로 그려지는 시점이 아니라 Lighthouse 12 시뮬레이터의 추정이었다.

| 측정 | LCP | 비고 |
|---|---|---|
| Lighthouse 12.8 운영 ×2 | 5.1s · 2.6s | 관찰된 LCP 는 1,344ms · 310ms — 둘 다 FCP 와 같다 |
| Lighthouse 13.6 운영 ×3 | 0.9s · 0.9s · 0.9s | |
| Playwright · CPU 4배 감속 · 412×823 운영 | 536ms | PerformanceObserver. 후보는 상품 설명 `<p>` 하나 |

- LCP 요소는 상품 설명 문단이고 서버 HTML 에 들어 있다. 지연은 전부 Render Delay 로 잡혔다
- 시뮬레이터는 "관찰된 첫 페인트 이전에 요청된 JS" 를 느린 4G · CPU 4배로 다시 계산한다. 첫 페인트가 늦게 잡힌 실행(1,344ms)에서는 three.js 청크(407KB)까지 들어가 5.1초, 빨리 잡힌 실행에서는 2.6초가 됐다
- 실제로 고칠 것은 하나였다: three.js 청크가 load 보다 150~240ms 먼저 요청되고 있었다(3D 초기화만 load 뒤였고 모듈 다운로드는 하이드레이션 직후). 모듈 요청도 load + 유휴 시간 뒤로 옮겼다(`src/three/idle.ts`, e2e `product.spec` 로 고정)
- 같은 로컬 조건 Lighthouse 12 ×3: TBT 460~800ms → 360~430ms, 점수 0.68~0.75 → 0.76~0.78. 시뮬레이션 LCP 는 3.5s 그대로(로컬은 원래 첫 페인트가 three.js 요청보다 앞섰다)
- 배포 뒤 운영(7a63976): Playwright · CPU 4배 감속 LCP 284 · 328 · 460ms(수정 전 536ms). Lighthouse 13.6 ×2 LCP 0.9s · 점수 0.82~0.83.
  Lighthouse 12 ×3 은 2.9 · 5.4 · 5.4s 였는데 이때 Lighthouse 가 관찰한 첫 페인트 자체가 2.0~2.4초였다(같은 시각 Playwright 측정은 0.3~0.5초, CDN HIT · TTFB 150ms).
  측정 기기 쪽 편차로 보고, Lighthouse 12 시뮬레이션 숫자는 이 페이지의 지표로 쓰지 않는다

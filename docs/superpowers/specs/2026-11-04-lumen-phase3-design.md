# LUMEN 3차 — 색 바꾸기 · 내 방에 놓아 보기

작성 2026-11-04. 사용자가 3차의 세부 판단을 Claude 에 맡겼다("니 판단에 맡길게 진행해줘").
1차 설계 3.3 · 3.4 장과 2차 설계 4.3 장(자동 배치를 시작 배치로)을 잇는다. **이 문서의 결정은 모두 Claude 가 정한 것이다** — 11장에 따로 모았다.

## 1. 왜 하는가

1 · 2차로 "3D 로 보고 → 담고 → 내 방에서 보고 → 결제하면 불이 켜진다" 가 끝까지 이어졌다.
3차는 면접관이 **보기만 하는 게 아니라 직접 만져 보고 결정하는** 경험을 더한다.

- 색 바꾸기: 같은 소파를 다른 천 색으로 돌려 보고, 고른 색 그대로 담고 주문한다
- 내 방에 놓아 보기: 내 방 크기를 넣고, 담은 가구를 끌어 옮기고 돌려 배치를 정한다

## 2. 목표 · 비목표 · 실패 조건

### 목표
- 천 · 가죽을 씌운 가구 7개에서 색을 고르면 3D 가 바로 그 색으로 바뀐다. 고른 색은 장바구니 · 주문 · 결제 완료 장면까지 따라간다
- `/room` 에서 방 크기(가로 · 세로 · 높이)를 넣으면 그 방에 장바구니 가구가 놓이고, 끌어 옮기기 · 90° 돌리기 · 위에서 보기가 된다
- 방에서 가구를 더하면 장바구니에도 담긴다 — "방 = 장바구니" 하나만 있다

### 비목표
- 탁자 · 선반 · 조명 · 화병의 색 옵션 (텍스처 한 장에 부위가 섞여 있고, 바꿀 이유도 약하다)
- 소재 자체(가죽 ↔ 패브릭) 바꾸기 — 모델 20개 중 14개가 재질 하나 · 텍스처 한 장이라 부위를 나눌 수 없다
- 배치를 서버에 저장 · 공유하기 (브라우저에만 저장)
- 벽 · 창문 · 문 그리기, 자유 각도 회전

### 실패 조건 (돌아가도 실패인 것)
- 색을 바꿨는데 나무 다리까지 같이 물들어 가짜처럼 보인다 (Ember 소파처럼 천 · 다리가 둘 다 어두운 모델은 목표색을 어둡게 잡아 티가 덜 나게)
- 색을 골라 담았는데 장바구니 · 주문에서 다른 색으로 보이거나, 같은 상품 다른 색이 한 줄로 합쳐진다
- 방에서 가구가 벽을 뚫거나, 휴대폰에서 끌기가 페이지 스크롤과 싸운다
- 3D 를 못 그리는 기기에서 `/room` 이 빈 화면

## 3. 소재 시험 결과 (2026-11-04, 설계 전에 해 봤다)

- 모델 20개 재질 조사: 14개는 재질 1개 · 텍스처 1장(천 + 나무가 한 장에). 부위가 나뉜 건 Halo 라운지 체어(쿠션 | 다리) · 화분 · 천장 조명 정도
- **선택적 재채색** 을 시험했다(`src/three/recolor.ts`): 텍스처 각 점이 천의 대표색에 얼마나 가까운지로 가림막을 만들고, 원래 밝기 비율을 지켜 새 색을 곱한다
  - Velvet 소파 · Moss 체어: 천만 바뀌고 조각 원목은 그대로 — 가장 자연스럽다
  - Halo 라운지 체어: 쿠션 재질만 통째로 — 깔끔하다
  - Classic 암체어: 밝은 결이 허용 범위를 벗어나 흰 얼룩 → 허용 범위를 넓혀야 한다
  - Ember 소파: 다리까지 물든다(둘 다 어둡다). 어두운 목표색이면 쓸 만하다
- 대표색은 텍스처를 k-means 로 4개 묶어 가장 넓은 묶음에서 잡았다(`.superpowers/palette.mjs` — 로컬 도구)

## 4. 색 바꾸기

### 4.1 대상과 색
| 상품 | 방식 | 색 (첫 번째 = 원래 색) |
|---|---|---|
| Velvet 2인 소파 | 대표색 재채색 | 아이보리 · 네이비 · 테라코타 · 세이지 |
| Classic 암체어 | 대표색 재채색 (넓은 허용) | 그레이 · 포레스트 · 머스터드 |
| Moss 체어 | 대표색 재채색 | 그린 · 버건디 · 차콜 |
| Halo 라운지 체어 | 쿠션 재질 통째 | 블랙 · 코냑 · 탠 |
| Ember 3인 소파 | 대표색 재채색 (어두운 목표색만) | 블랙 · 다크 브라운 · 옥스블러드 |
| Pebble 오토만 | 재질 통째 | 블랙 · 코냑 · 그레이 |
| Siesta 데이베드 | 매트 대표색 재채색 | 내추럴 · 차콜 · 더스티 로즈 |

- 정확한 목표색 · 대표색 · 허용 범위는 구현하면서 스크린샷으로 맞춘다(빌더에게 맡김). 원칙: 원래 텍스처의 결 · 주름이 살아 있고, 나무가 물들지 않을 것
- 가격은 색과 상관없이 같다

### 4.2 데이터
- 상품 정보는 계속 코드(`src/catalog/products.ts`)에. 상품에 `colors?: ColorOption[]` — `{ id, label, swatch(hex), recolor?: Recolor }`. 첫 항목이 원래 색이고 `recolor` 가 없다
- 장바구니 · 주문의 한 줄은 **(상품, 색)** 이다. 같은 소파 네이비 · 아이보리는 두 줄
  - `CartItem` 에 `color String @default("")`, 기본키 `(userId, productSlug, color)`. `""` = 원래 색(색 옵션 없는 상품도 `""`)
  - `OrderItem` 에 `color String @default("")` · `colorLabelSnapshot String?` (주문 당시 이름)
  - 마이그레이션 0003 은 **더하기만** 한다(기본값 있는 열 · 기본키 교체). 운영 DB 에 먼저 적용하고 코드를 배포한다 — 옛 코드는 새 열을 몰라도 돌아간다
- 브라우저 장바구니 줄 `{ slug, quantity, color? }`. 로그인 순간 합치기 · 끊긴 요청 재전송(2차 수정)의 열쇠도 `slug|color`
- 카탈로그에 없는 색 id 는 서버가 `""` 로 바꾼다 (가격처럼 브라우저 값을 믿지 않는다)

### 4.3 화면
- 상품 상세: 담기 위에 색 견본 줄(동그라미 · 이름). 고르면 3D 가 즉시 바뀌고(재질 교체, 모델은 다시 받지 않는다) 주소에 `?color=<id>` — 정적 페이지는 그대로 두고 클라이언트가 읽는다
- 장바구니 목록 · 주문서 · 주문 상세: 상품 이름 옆에 색 견본 + 이름
- 장바구니 방 · 결제 완료 장면 · 내 방: 고른 색으로 그린다
- 상품 목록 썸네일 · 쇼룸은 원래 색 그대로

## 5. 내 방에 놓아 보기 (`/room`)

### 5.1 흐름
- 들어오는 곳: 쇼룸 둘러보기의 `내 방에 놓아 보기`(지금 비활성 버튼을 살린다) · 장바구니 화면 `내 방 크기로 놓아 보기` · 상품 상세 `내 방에 놓아 보기`(담고 이동)
- 처음 열면 방 크기는 자동 배치가 정한 크기(기본 4 × 4m, 높이 2.6m). 가로 · 세로 2.0 ~ 8.0m, 높이 2.2 ~ 3.5m, 0.1m 단위
- 배치는 장바구니로 만든다. 처음엔 자동 배치(`arrangeRoom`)를 **입력한 방 크기 안에서** 돌린 결과. 자리가 모자라 못 놓은 가구는 방 가운데에 겹친 채 두고 "겹쳐요" 로 표시
- 장바구니가 비었으면 빈 방 + `가구 더하기`

### 5.2 조작
- 가구를 눌러 고르면 윤곽이 밝아지고 아래에 이름 · 치수
- 끌기: 바닥 평면 위로. 5cm 단위로 맞추고, 돌린 상태의 바닥 크기로 벽 안쪽에 가둔다. 천장 조명은 천장 높이에서 끈다
- 돌리기: 고른 가구의 ⟲ ⟳ 버튼(90°), 키보드 `Q` · `E`
- 키보드: 화살표로 10cm 씩, `Shift` + 화살표 50cm — 접근성이자 e2e 의 손잡이
- 겹침: 바닥 가구끼리 바닥 크기가 겹치면 둘 다 붉은 윤곽 + 목록에 "겹쳐요"
- 위에 놓는 것(화병 · 캔들 홀더): 탁자 · 선반 위에 놓으면 그 상판 높이에, 아니면 바닥에
- 카메라: 기본은 비스듬히(장바구니 방과 같은 제한된 둘러보기), `위에서 보기` 토글로 수직 시점 — 배치는 위에서 정하는 게 편하다
- 오른쪽(휴대폰은 아래) 목록: 가구 · 색 · 수량, 빼기 · 수량, `가구 더하기`(상품 목록 서랍 → 담기 = 장바구니에 담김), `처음 배치로`, `장바구니로`

### 5.3 저장
- 브라우저(localStorage `lumen-room`)에 `{ size, placements }`. 배치의 열쇠는 `slug|color#instance`
- 장바구니가 바뀌면 맞춘다: 새로 생긴 가구는 빈 자리에 자동으로, 사라진 가구는 지운다, 남은 가구는 그대로
- 로그인 여부와 상관없다 (서버에 안 보낸다)

### 5.4 기기
- 휴대폰: 가구 위에서 끌면 가구가 움직이고, 빈 곳에서 끌면 시점이 돈다. 끄는 동안은 페이지 스크롤을 막는다(`touch-action: none` 은 캔버스에만)
- 품질 단계 · 폴백은 1차 `Stage3D` 그대로. 3D 를 못 그리면 방 대신 "이 기기에서는 3D 를 그릴 수 없어요" + 장바구니 링크

## 6. 만드는 방식 (고려한 것)

### 색 바꾸기
- **A. 선택적 재채색 셰이더 (고름)** — 텍스처 한 장 모델에서도 천만 바꾼다. 시험으로 확인했다. 모델마다 대표색 · 허용 범위를 맞추는 손이 든다
- B. 재질 전체 틴트 — 쉽지만 나무까지 물든다. 시험 전 가정에서 버렸다
- C. 색마다 텍스처를 새로 만들어 받기 — 가장 정확하지만 모델 × 색 수만큼 에셋이 늘고(1k · 2k 둘), 색 바꿀 때마다 내려받는다

### 장바구니에 색 넣기
- **A. (상품, 색) 을 한 줄로 — DB 기본키에 색 (고름)** — 주문까지 색이 정확히 따라간다. 마이그레이션 한 번
- B. 색은 미리보기만, 장바구니에는 안 들어감 — 마이그레이션이 없지만 "고른 색을 산다" 가 안 된다. 2차의 "구매까지 이어진다" 와 어긋난다

### 내 방 배치
- **A. 장바구니를 그대로 방으로 · 브라우저 저장 (고름)** — 2차 자동 배치를 시작 배치로 그대로 쓴다. 서버 · 마이그레이션 없음
- B. 카탈로그에서 아무거나 골라 놓는 별도 플래너 — 장바구니와 따로 노는 두 번째 목록이 생긴다
- C. 배치를 서버에 저장 — 기기를 바꿔도 남지만 데모 계정은 24시간이면 지워진다. 지금 얻는 게 적다

## 7. 테스트
- 단위: 재채색 설정 검증(색 id · 첫 항목 원래 색), 줄 열쇠 `slug|color` 의 더하기 · 합치기 · 빼기, 방 안에 가두기 · 5cm 맞춤 · 90° 돌린 바닥 크기, 겹침 판정, 상판 위 높이, 고정 크기 자동 배치(넘치면 가운데), 저장된 배치와 장바구니 맞추기
- 통합(DB): 같은 상품 두 색이 두 줄, 없는 색 id 는 `""`, 주문 줄에 색 · 이름이 남는다
- e2e: 색 고르면 주소 · 견본 선택 상태가 바뀌고 담으면 장바구니에 색 이름, 두 색은 두 줄, 결제 완료까지 색 유지. `/room`: 크기 바꾸기, 키보드로 옮기면 위치 표시가 바뀌고 벽에서 멈춘다, 돌리기, 새로고침해도 배치 유지, 가구 더하기 → 장바구니 수 증가, 3D 불가면 안내
- 화면: 색마다 스크린샷으로 나무가 물들지 않았는지 본다

## 11. Claude 가 정한 것 (사용자 검토용)
1. 순서: 색 바꾸기를 먼저(해 봐야 아는 쪽), 내 방은 그다음
2. 색 바꾸기 방식: 선택적 재채색 셰이더 — 시험 결과로 정했다
3. 대상: 천 · 가죽 가구 7개만, 탁자 · 선반 · 조명 · 화병은 색 옵션 없음
4. 색은 장바구니 · 주문까지 따라간다(DB 마이그레이션 0003), 가격은 같다
5. 내 방에 놓는 가구 = 장바구니. 방에서 더하면 장바구니에 담긴다
6. 배치는 브라우저에만 저장
7. 회전은 90° 단위, 벽 · 창문은 그리지 않는다
8. 위에서 보기 시점을 넣는다
9. 소재 자체 바꾸기는 하지 않는다 (모델 구조상 불가능)

# NOCTURNE — 3D 가구 쇼핑몰 설계

- 작성일: 2026-11-02
- 상태: 사용자 검토 대기
- 이름 `NOCTURNE`(폴더 `nocturne`)은 시안에서 쓴 **가칭**이다. 바꿔도 설계는 그대로다.

## 1. 왜 만드는가

포트폴리오 사이트(`../portfolio`)의 5번째 카드 **SHOPPY**가 경쟁력이 없다는 평을 들었다.
SHOPPY를 내리고 그 자리에 이 프로젝트를 올린다.

- 지원 직무: **프론트엔드**. 회사는 정해 두지 않았다 → 특정 업계보다 **넓게 통하는 것**이 낫다
- 지금 포트폴리오 4개(Nextour · 명당재팬 · Seoul Date · SEFLIX)에는 **3D·그래픽을 다루는 프로젝트가 없다**.
  이 프로젝트는 그 빈자리를 채운다
- SHOPPY와 같은 커머스 도메인을 이어받아 **"같은 분야를 훨씬 높은 수준으로 다시 만들었다"** 는 이야기가 된다
- 기한은 없다. **되는 대로 빨리** 올린다 → 단계별로 끊어 올린다 (6장)

## 2. 목표 · 비목표 · 실패 조건

### 목표
1. 첫 화면에서 **"이 사람 3D 잘하네"** 가 나오는 시네마틱 3D 쇼룸
2. 실제로 **주문·테스트 결제까지 되는** 쇼핑몰
3. **기기·GPU 상황에 따라 품질을 자동으로 조절**해 저사양에서도 버벅이지 않는다 — 그리고 그 효과를 **숫자로 남긴다** (전/후 fps 등)
4. 3D 기능 세 가지: 쇼룸 · 상품 상세 3D(회전·소재/색 변경·치수) · 내 방에 놓아 보기

### 비목표
- 실제 판매·재고·배송. 상품·가격은 **가짜 데이터**다
- 관리자(상품 등록) 화면
- AR(카메라로 실제 방에 띄우기)
- 다국어 — 한국어만

### 실패 조건 (돌아가도 실패인 것)
- **저사양 노트북이나 폰에서 버벅인다** — 화려함보다 이게 먼저다. 면접관이 아무 기기로 열어도 매끄러워야 한다
- **첫 화면이 오래 하얗거나 까맣다** — 3D 에셋을 다 받을 때까지 아무것도 안 보이는 상태
- 효과는 화려한데 **쇼핑몰로서 쓰기 불편하다** (가격·장바구니·결제가 잘 안 읽힘)
- 에셋 출처 표기 누락 (Poly Haven 조건, 4장)

## 3. 화면과 흐름

### 3.1 톤 — 다크 시네마틱 (사용자 선택: 시안 B)
- 어두운 공간, 스포트라이트 아래의 가구, 따뜻한 조명색
- **사이트 전체를 다크로 통일한다** (Claude 판단 — 첫 화면만 어둡고 나머지가 밝으면 다른 사이트처럼 보인다)
- 장바구니·주문·결제 화면은 3D 연출을 빼고 **읽기 쉬움을 우선**한다

### 3.2 첫 화면 쇼룸 (사용자가 "가장 화려하고 전문적으로" 를 Claude 에 맡겼다 → Claude 판단)
1. **도입** — 어둠 속에 스포트라이트가 켜지고 대표 가구 하나가 천천히 돌며 등장
2. **스크롤** — 대표 가구 4~5개가 차례로 조명 아래로. 이름·가격·소재가 함께 뜬다
3. **피날레** — 조명이 하나씩 켜지며, 지금까지 본 가구가 함께 놓인 **방 전체**가 드러난다
4. **둘러보기** — 방을 돌려 보고, 가구를 누르면 상품 상세로. "내 방에 놓아 보기" 진입점도 여기

### 3.3 상품 상세
- 3D 360° 회전 · 확대
- **소재·색 바꾸기** (Poly Haven 텍스처) — ⚠️ 모델마다 UV가 달라 자연스러운지 **직접 해 봐야 안다** → 3차에 두고 그 전에 몇 개로 시험한다
- 치수 표시

### 3.4 내 방에 놓아 보기
- 방 가로·세로(·높이)를 입력 → 그 크기의 빈 방
- 가구를 끌어 옮기고 돌린다. 장바구니 담기와 이어진다

### 3.5 쇼핑몰 기본
- 상품 목록 · 카테고리: 의자·소파 / 테이블 / 선반 / 침대 / 조명 / 소품
- 로그인 · 장바구니 · 주문 · **토스페이먼츠 테스트 결제** · 주문 내역

## 4. 데이터 — Poly Haven

- API: `https://api.polyhaven.com` (2026-11-02 확인)
- **2026-07 부터 상업적 이용 포함 무료.** 조건: **"에셋 출처가 Poly Haven" 임을 사용자에게 분명히 표시** → 푸터 + 상품 상세에 출처 표기
- 에셋은 CC0
- 쓸 수 있는 양 (2026-11-02):
  - 가구 모델 85 — 의자·소파 34 · 테이블 27 · 선반 16 · 침대 3
  - 조명 29 · 장식 76 · 식물 57
  - 텍스처 — 나무 138 · 패브릭 43 · 가죽 6 · 금속 25
  - HDRI(조명용 배경)
- 상품 정보(가격·설명·재고 수)는 **우리가 만든 가짜 데이터**를 DB에 둔다. 모델은 Poly Haven 에셋 ID로 잇는다

### 에셋을 어떻게 받나 (Claude 판단)
**빌드 단계에서 받아 최적화한 뒤 우리 쪽에서 내준다.** 런타임에 Poly Haven 원본을 직접 받지 않는다.
- 원본은 텍스처가 크다(4K 등) → 첫 화면 지연·모바일 메모리 문제. 실패 조건 2와 바로 충돌한다
- 받는 단계에서 메시 압축 · 텍스처를 KTX2 등으로 변환 · 해상도 단계별(저/중/고) 생성
- 품질 조절(5장)이 이 단계별 에셋을 고른다
- 출처 표기는 그대로 한다

## 5. 기기·GPU 대응 — 이 프로젝트의 기술적 핵심

- **렌더러: WebGPU 우선, 안 되면 WebGL2로 자동 대체.** Three.js 의 WebGPU 렌더러 사용
  - ⚠️ 브라우저 지원 범위와 R3F 에서 WebGPU 렌더러를 쓰는 방식은 **구현 시점에 다시 확인**한다
- **처음 접속 때 등급 판정** — GPU 등급(`detect-gpu` 등) + 화면 크기·픽셀 밀도로 시작 품질을 정한다
- **실행 중 조절** — 프레임 속도를 보며 단계적으로 내리고 올린다 (R3F `PerformanceMonitor` 류)
  - 조절 대상: 렌더 해상도(DPR) · 그림자 품질 · 반사·후처리 효과 · 에셋 해상도
- **WebGL 도 안 되는 환경** — 3D 대신 정적 이미지로 대체. 쇼핑은 그대로 된다
- **측정을 남긴다** — 저사양 기준 기기에서 전/후 fps, 첫 화면 표시 시간. 포트폴리오 카드와 README 에 쓴다

## 6. 단계 (사용자 확정)

| 단계 | 내용 | 끝나면 |
|---|---|---|
| **1차** | 쇼룸 첫 화면(3.2 전부) · 상품 목록 · 상품 상세 3D 회전 · **품질 자동 조절(5장)** · 에셋 파이프라인 · 배포 | **SHOPPY 를 내리고 포트폴리오 교체** |
| **2차** | 로그인 · 장바구니 · 주문 · 토스 테스트 결제 · 주문 내역 | 포트폴리오 카드 갱신 |
| **3차** | 소재·색 바꾸기 · 내 방에 놓아 보기 | 포트폴리오 카드 갱신 |

순서 이유: 첫인상(쇼룸)과 기기 대응을 먼저, 이미 해 본 결제는 뒤로, 해 봐야 아는 소재 바꾸기는 마지막.

## 7. 만드는 방식

### 고려한 것
| | A. Next.js 풀스택 하나 | B. 3D 프론트 + 쇼핑몰 서버 분리 | C. Vite SPA + 서버리스 결제 |
|---|---|---|---|
| 장점 | Nextour 의 결제·로그인을 그대로 가져온다. 상품 페이지를 서버에서 그려 첫 로딩·검색 노출이 좋다 | 프론트/백 분리 설계를 보여준다 | 가장 단순, 3D 에만 집중 |
| 단점 | 기술 구성이 Nextour 와 비슷 (차별점은 3D 라 괜찮다) | 만들 것·배포할 것이 두 배 — "빨리" 와 안 맞는다 | 회원·주문 저장이 어렵고 상품 페이지가 검색에 안 잡힌다 |

### 고른 것: **A** (사용자 선택)
이유: 빨리 올린다 → 해 본 결제·로그인은 가져다 쓰고 시간을 3D 에 몰아준다. 포트폴리오 사이트도 Next.js 16 이라 흐름이 일관된다.

### 정해진 구성
- Next.js 16 (App Router) · React 19 · TypeScript
- Three.js + React Three Fiber (+ drei)
- Prisma + Postgres · Auth.js
- 토스페이먼츠 SDK v2 (테스트 키)
- 배포: Vercel

### 참고할 기존 코드 (Nextour, `../travel`)
- 결제: `src/shared/lib/toss/client.ts` · `src/features/checkout/ui/PaymentWidget.tsx` · `src/features/checkout/ui/ConfirmPayment.tsx` · `src/app/api/payments/webhook/toss/route.ts`
- 결제 도메인 CSP: `src/shared/lib/security/csp.ts`

## 9. Claude 가 정한 것 (사용자 검토용)
- 사이트 전체 다크 톤 (3.1)
- 첫 화면 구성: 스크롤 스포트라이트 → 방 공개 → 둘러보기 (3.2)
- 에셋을 빌드 단계에서 받아 최적화 (4장)
- WebGPU 우선 + WebGL2 대체 (5장)
- WebGL 불가 환경은 정적 이미지 대체 (5장)
- 비목표 목록 (2장)
- 가칭 NOCTURNE
- **주문·결제는 로그인한 사용자만** (Nextour 와 같은 방식). 장바구니 담기는 비로그인도 된다
- 성능 목표: 데스크톱 **60fps**, 저사양 노트북·중급 폰 **30fps 이상**을 지킨다
- 모바일도 1차부터 대상이다 — 쇼룸 스크롤은 터치에서도 같은 흐름으로 동작한다
